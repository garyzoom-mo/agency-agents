# 阶段 1：策略规格与能力边界

> 目标：在写第一行策略代码之前，把「赚什么钱、在什么条件下会亏、参数有多少自由度、结果以什么形态交付给通达信」写清楚。
> 这一步做扎实，阶段 3 的过拟合风险能砍掉一大半。

## 输入 / 输出

- **输入**：`{{策略名}}` `{{一句话假设}}` `{{标的池}}` `{{信号频率}}` `{{交付物形态}}`
- **输出**：① 8 节策略规格书 ② 能力边界判定 ③ 桥接方式决策 ④ 参数清单（含待优化范围）⑤ 失效条件清单

## 1. 策略规格书（8 节，缺一节不许进阶段 2）

用 `templates.md` 的 **T1** 模板。每节的最低要求：

| # | 章节 | 最低要求（做不到就是没写） |
|---|------|--------------------------|
| 1 | 一句话假设 | 形如"X 在 Y 条件下会 Z，因为 W"。禁止出现"大概率""应该能" |
| 2 | 经济/行为逻辑 | 这个收益是谁在亏给你？如果答不出来，大概率是噪音 |
| 3 | 标的池与频率 | 明确的代码来源（指数成分、板块、自定义列表）+ 信号频率 + 调仓频率 |
| 4 | 信号定义 | 输入数据 → 判断 → 输出值域（如 1/0/-1），用可执行语言写，不用"强势""放量"这类词 |
| 5 | 仓位与资金 | 目标仓位算法、单票上限、总仓位上限、调仓步长（股数/手数） |
| 6 | 风控与红线 | 止损、最大回撤停机、黑名单（ST/退市/停牌/涨跌停不可成交）、T+1 约束 |
| 7 | 成本与成交假设 | 手续费口径、滑点是否建模、成交时点（收盘后决策→次日开盘？） |
| 8 | 失效条件 | **这个策略在什么情况下应该亏钱**（写不出=没理解策略）；以及什么信号说明"假设已死" |

## 2. 能力边界表（先分清谁干什么）

| 事情 | Python / TqSdk | 通达信公式 |
|---|---|---|
| 历史数据获取 | ✅ 全合约 tick/分钟/K 线，支持复权 | ⚠️ 只用本地已下载数据；缺数据会静默 |
| 复杂计算（矩阵、ML、优化、统计检验） | ✅ | ❌ 只有逐 K 线向量运算，难做截面/联合优化 |
| 循环体策略（持仓状态机、逐笔撮合） | ✅ 事件驱动 `wait_update()` | ❌ 公式是逐 K 线求值，没有真正的循环与状态 |
| 外部数据（财报、公告、另类数据） | ✅ | ❌ 无法联网 |
| 下单 | ✅ 支持期货/期权/A股实盘与模拟 | ⚠️ 仅本地下单/预警，需券商客户端配合 |
| 盯盘、画图、盘口、手工干预 | ⚠️ 要自己搭界面 | ✅ 这是它的主场 |
| 与券商交易终端的原生联动 | ❌ | ✅ |

**结论**：复杂逻辑放 Python；看得见、点得动、下单顺手的那部分放通达信。不要试图用通达信公式复刻 Python 策略（选股类简单条件除外）。

## 3. 桥接方式决策（本工作流的核心选择）

```
信号频率是日频还是盘中？
├── 日频（收盘后算一次，次日用）
│   ├── 需要在图上/副图看数值序列 → 自定义序列数据（SIGNALS_USER）
│   ├── 只需要每票一条的最新状态/备注（评级、动作、理由）→ 外部数据（EXTERNSTR/EXTERNVALUE）
│   └── 只需要"今天选中哪些票"→ 自定义板块 .blk（最好用，通达信原生体验）
└── 盘中（分钟级刷新、要立刻在通达信里看到）
    ├── 能接受"每 N 秒重写文件 + 通达信重进视图" → 仍然走文件桥（最简单，推荐先这样）
    └── 要求秒级、免手工刷新 → 才考虑 TDXDLL 自绘通道（要 C 编译器，成本最高）
```

**优先级铁律**：文件桥 > 官方 txt 导入 > DLL。能用简单方案就别上复杂方案；DLL 只在"文件桥的刷新延迟已经影响交易"时才上。

## 4. 参数清单与自由度预算

把参数写成表格（它同时是阶段 3 的测试矩阵输入）：

| 参数 | 含义 | 默认值 | 待优化范围 | 为什么这个范围 | 是否稳健平台区 |
|---|---|---|---|---|---|
| `fast` | 快线周期 | 5 | 3–10 | 常见趋势周期 | 待阶段 3 填 |
| `slow` | 慢线周期 | 20 | 15–40 | 一个月交易日量级 | 待阶段 3 填 |
| `vol_max` | 开仓允许最大日波动 | 0.05 | 0.02–0.08 | 控制极端波动入场 | 待阶段 3 填 |

**自由度预算（硬约束）**：在样本量 N 个交易日的回测里，可优化参数个数 k 满足 **N / k ≥ 100**。
例如 500 个交易日最多优化 5 个参数。超了就必须做多重比较校正，否则你优化出来的只是噪音（Statistician 铁律 5）。

## 5. 失效条件清单（"论点失效"触发器）

每一行都要能在阶段 6 被监控脚本自动检查：

| 失效条件 | 判定方式 | 触发后动作 |
|---|---|---|
| 滚 60 日超额收益 ≤ 0 | 每日对账脚本计算 | 降半仓并人工复核 |
| 单票回撤 > 15% | 持仓表逐票检查 | 信号层面强制置 0 |
| 信号连续 10 个交易日不变（可能数据没更新） | 与上一日信号对比 | 报警，检查数据管道 |
| 实盘滑点 > 回测假设 2 倍 | 成交回报 vs 回测 | 暂停，重估成本模型 |

## 6. 与通达信对接的契约（写进规格书）

```
数据号约定：
  序列数据 100 → 每日目标仓位（1 / 0 / -1），逐日写满（含未持仓日）
  外部数据 101 → 最新动作文字（"09-17 开多"），含日期前缀，便于肉眼核对
  板块    TQ_SIGNAL → 今日信号为 1 的股票清单
K 线口径：通达信侧不需要复权（信号是 0/1 状态值）；若信号含价格，必须注明复权口径
刷新时机：收盘后 15:30 由计划任务写入；次日开盘前人工确认一次
异常处理：任一步失败 → 不落盘 + 退出码非 0 + 日志留痕（宁可今天没信号，也不要写半截）
```

## 8. 常见反模式（见到就打回）

1. **用"我感觉"代替假设**："最近这种图形涨得好" → 不是策略，是观察。先把它写成可测规则。
2. **先优化参数再想逻辑**：网格搜索出来的最佳参数点，几乎都是曲线拟合。
3. **拿通达信当计算引擎**：把 Python 能轻松算的截面因子写成几百行公式 → 维护地狱，直接桥接。
4. **没有失效条件**：任何策略都会失效，区别只在于你是"提前定义好什么时候退出"，还是"亏到受不了才退出"。
5. **在规格里就写"自动下单"**：首次上线一律只出信号，人工确认。
