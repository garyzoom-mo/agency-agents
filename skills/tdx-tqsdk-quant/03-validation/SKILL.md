# 阶段 3：回测有效性与证据

> 目标：把"我回测过了"变成"这份回测经得起我自己三个月后复核"。
> **默认立场是 NEEDS WORK**：单一区间、单组参数的好看曲线，不构成任何结论。

## 输入 / 输出

- **输入**：阶段 2 的策略代码与参数表
- **输出**：① 未来函数检测报告 ② 成本/成交假设清单 ③ 样本内/外与稳健性结果 ④ 回测报告 JSON（证据）⑤ GO/NO-GO 裁决

## 1. 未来函数（look-ahead）—— 一票否决项

三种检测手段，**至少前两种必须做**：

### 1.1 前缀稳定性测试（自动化，推荐）

原理：合法策略在 t 日的信号只依赖 t 日及之前的数据。用前 t 根 K 线算出的历史信号，必须与全量数据算出的同一天信号完全一致。

```python
# reference/example_strategy.py 已实现，直接调用
from example_strategy import assert_prefix_stable, compute_position_signals, load_bars_demo
bars = load_bars_demo("SSE.600519")
assert_prefix_stable(bars, lambda b: compute_position_signals(b, fast=5, slow=20))
```

会抓到这些作弊：按全样本最大值归一化、`shift(-1)`、用未收盘的最后一根 K 线、用未来日期做 join。
配套的**反向测试**（用故意作弊的函数验证检测器有效）见 `reference/test_example_strategy.py::TestLookaheadGuard`。

### 1.2 人工走查清单

| 检查点 | 反例 | 正确写法 |
|---|---|---|
| 未完成 K 线 | `klines.iloc[-1].close` 直接参与信号 | `klines.iloc[:-1]` 或等 `is_changing(...,"datetime")` |
| 全样本统计量 | 用整段回测的均值/标准差做标准化 | 用**滚动窗口**或**扩展窗口**统计量 |
| 未来函数指标 | 通达信侧用 `ZIG`/`BACKSET`/`REFX` 做预警 | 只用 `REF/MA/EMA` 等回看函数 |
| 数据可得性 | 用当日收盘财务数据在当日盘中决策 | 财报按**披露日**对齐，不按报告期 |
| 退市/成分变更 | 用"今天"的指数成分回溯历史 | 用**时点成分**；没有就用替代方案并标注 |
| 停牌缺口 | 让信号在停牌日成交 | 只在有行情的交易日成交 |

### 1.3 与通达信逐日对齐（阶段 5 交叉验证）

导出后用 `verify` 模式把通达信目录里的数据读回来，与 Python 内存里的信号逐日比对，
差异必须为 0（或全部能解释）。这是唯一能证明"桥真的通了"的证据。

## 2. 成本与成交假设（不写清楚 = 结论无效）

| 项目 | 必须明确 | 常见默认（要写进报告） |
|---|---|---|
| 手续费 | 按什么口径算 | 期货：`TqSim.set_commission` 可覆盖；股票模拟账户 3.10.x 无此接口，按行情默认 |
| 滑点 | 建模了没有 | **TqSdk 未建模** → 必须做敏感性分析 |
| 成交时点 | 收盘后决策 → 何时成交 | 次日开盘（回测里表现为下一根 K 线的 tick） |
| 涨跌停 | 一字板无法成交怎么办 | 未建模 → 人工核对信号是否落在涨停板 |
| 停牌 | 停牌期间仓位处理 | 未建模 → 用交易日对齐规避 |
| T+1 | A 股当日买入不可卖出 | 未建模 → 信号频率必须 ≥ 日频，且人工核对 |
| 换手成本 | 调仓频率带来的成本 | 报告里必须给出年化换手与成本占比 |

**成本敏感性矩阵（必做）**：把收益率在以下情景重算/折算，结论里给区间而不是单点。

| 情景 | 手续费 | 滑点 | 结论 |
|---|---|---|---|
| 基准 | 交易所默认 | 0 | 参考上界 |
| 保守 | ×2 | 单边 0.1% | 常见现实 |
| 严苛 | ×2 | 单边 0.2% | 下界 |

> 判据：严苛情景下仍然有正的、且与零有实质距离的收益 —— 才算"成本之后还有肉"。

## 3. 样本划分与稳健性（三条，缺一不可）

1. **样本外验证**：训练区间与测试区间不重叠。报告必须同时给出两段的表现，
   **样本外显著变差是常态**，差多少决定你还敢不敢上。
2. **Walk-forward 滚动**：训练 24 个月 → 测试 6 个月 → 前滚，重复 ≥ 4 次。
   报告给出每次的收益/回撤，而不是只报总收益。
3. **参数稳健性（高原 vs 尖峰）**：把每个参数在范围内上下扫（如 `fast` 3→10，步长 1），
   画收益曲面。判据：**最佳点周围 ±20% 的参数变化后，表现不应崩塌**（例如衰减 < 50% 且仍为正）。
   尖峰 = 拟合；高原 = 相对可信。

## 4. 统计纪律（避免"用噪音造结论"）

| 纪律 | 落地做法 |
|---|---|
| 自由度预算 | 回测 N 个交易日，最多优化 N/100 个参数；超了必须校正 |
| 多重比较 | 测了 m 组参数，显著性阈值收紧为 α/m；或直接标注"探索性结果，未校正" |
| 报区间不报点 | 收益/回撤都要给区间与置信区间；不要只报一个夏普 |
| 效应量 vs 显著性 | "显著"不等于"值得交易"：扣成本后的年化必须过得去 |
| 样本量下限 | 交易笔数 < 30 的结论一律标注"样本不足，不可下结论" |
| 安慰剂测试 | 把信号日期随机打乱（或随机选票）跑同样的回测：真策略应显著优于安慰剂 |

**安慰剂测试一句话判据**：如果随机信号的收益和你的策略差不多，那你测的是市场 beta，不是策略。

## 5. 证据化验收（报告必须长这样）

每次回测输出一份 JSON（`reference/example_backtest.py` 已实现），至少包含：

```json
{
  "run_at": "...", "engine": {"name": "tqsdk", "version": "3.10.2"},
  "period": {"start": "2023-01-01", "end": "2024-12-31"},
  "symbols": ["..."], "params": {"fast": 5, "slow": 20},
  "data": {"kline": "日线", "adjust": "前复权", "used_bars": "只用到已收盘K线"},
  "execution_assumptions": { "...未建模项必须显式列出..." },
  "stats": {"ror": 0.0, "annual_yield": 0.0, "max_drawdown": 0.0, "sharpe_ratio": 0.0,
            "sortino_ratio": 0.0, "winning_rate": 0.0, "profit_loss_ratio": 0.0, "commission": 0.0},
  "known_gaps": ["未做成本敏感性", "未做样本外"]
}
```

**AUTOMATIC FAIL 触发条件**（出现任何一个，直接判 NEEDS WORK，不接受辩解）：

1. 报告里出现"零问题""完美""可以直接上实盘"这类措辞
2. 只有一条净值曲线，没有月度收益表 / 回撤表 / 交易明细
3. 没有说明成本与成交假设
4. 未做样本外，或做样本外但没报告样本外结果
5. 参数是网格搜索选出的最佳点，且没有稳健性检查
6. 交易笔数 < 30
7. 回测数据区间包含"策略设计时所处的行情"却未加标注

## 6. 质量门：GO / NO-GO

| # | 判据 | 证据 | 通过？ |
|---|------|------|--------|
| 1 | 前缀稳定性测试通过（含反向测试验证检测器有效） | 测试输出 | ☐ |
| 2 | 成本敏感性三情景已算，严苛情景结论明确 | 敏感性表 | ☐ |
| 3 | 样本外与 walk-forward 结果已出 | 报告 | ☐ |
| 4 | 参数稳健性为"高原"而非"尖峰" | 参数曲面图/表 | ☐ |
| 5 | 安慰剂测试：策略显著优于随机 | 对照结果 | ☐ |
| 6 | 多重比较已校正或已标注探索性 | 报告第 4 节 | ☐ |
| 7 | 回测 JSON 已落盘并含 known_gaps | 文件路径 | ☐ |

- **GO** → 进入阶段 4（信号导出）
- **NO-GO** → 回到阶段 1 改假设，或降低仓位预期后重测。**不许跳过本阶段直接写盘上线。**

## 7. 常见自欺清单

1. **区间挑到好看为止**（backtest hopping）：换区间直到曲线漂亮 —— 这是最普遍的过拟合。
2. **只调仓不扣成本**：高换手策略在成本面前经常直接归零。
3. **用"夏普 2.5"当结论**：没有区间、没有成本、没有样本外，这个数字没有信息量。
4. **忽略幸存者偏差**：标的池用"今天的成分股"回溯历史，天然滤掉了当年退市/被剔除的票。
5. **把一次回测当验证**：回测是必要的，远不是充分的 —— 真正的验证是**小仓位实盘 + 逐日对账**。
