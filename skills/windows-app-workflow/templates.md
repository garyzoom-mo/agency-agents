# 模板库（配合各阶段 skill 使用）

## T1. PRD 模板（阶段 1）

```markdown
# PRD：{{软件名称}}

## 1. 问题陈述
[用户的痛 + 现状为什么不行，一段话]

## 2. 目标与成功指标
- North Star：[1 个]
- 辅助指标：[2–3 个，如 7 日留存 / 周活跃打开 / 崩溃率 <0.5%]

## 3. 非目标（本版本明确不做）
- [ ] ...
- [ ] ...

## 4. 用户画像与故事
- Persona A：[一句话画像]
  - 作为 A，我想要 X，以便 Y。
  - ...

## 5. 方案概述（MVP 功能 ≤5 个）
| 功能 | 描述 | 验收标准（可测量） | RICE 分 |
|---|---|---|---|

## 6. 技术考量
- 运行时候选：[Electron / Tauri / 原生，初步倾向]
- 数据位置：%APPDATA%\{{AppName}}\
- 联网需求：[纯本地 / 需要联网的原因]

## 7. 发布计划
- 渠道：[ ]　版本规则：SemVer　更新策略：[自动/手动]

## 8. 风险与回滚
| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|

## 决定：GO / NO-GO（附理由）
```

## T2. ADR 模板（阶段 2，每个重要决策一份）

```markdown
# ADR-NNN: [决策标题]
## 状态: Proposed | Accepted | Superseded by ADR-XXX
## 背景: 什么问题迫使我们决策？
## 选项: 至少两个，各写代价
## 决定: 选了什么？
## 后果: 什么变容易、什么变难？（权衡，不只写好处）
```

## T3. IPC 契约模板（阶段 2/5）

```
| 通道名 | 方向 | 输入（校验规则） | 输出 | 备注 |
|---|---|---|---|---|
| project:create | renderer→main | { name: string ≤120 } | ProjectMeta | 写入 %APPDATA%\app\projects |

要求：
- 每个通道在特权侧校验（zod / 显式校验）
- 窄动词，无通用文件/Shell 通道
- 全部通道可在本文件枚举（审计目标）
```

## T4. Sprint 模板（阶段 5，每周）

```markdown
# Sprint N（MM-DD ~ MM-DD）
## 目标：[一句话，本周末可演示的东西]
## 任务
- [ ] 任务 1（验收标准：...）
- [ ] 任务 2（验收标准：...）
## 不做：[本周明确砍掉的]
## 周末评审结论：
## 回顾（最痛的一点 + 下周一项改进）：
```

## T5. Reality Check 报告模板（阶段 6）

```markdown
# Reality Check — {{软件名称}} vX.Y.Z
## 裁决：READY / NEEDS WORK（默认 NEEDS WORK，直到证据充分）
## 证据包
- 干净机器全流程截图：安装 → 首启 → 核心流程 → 导出 → 更新 → 卸载
- 测试报告：[链接/路径]
- 性能基准：[链接/路径]
## 声明核对表（每条声明 → 证据）
| 声明 | 证据 | 核对结果 |
|---|---|---|
## 自动失败触发器检查
- 核心旅程断裂？[ ]　崩溃？[ ]　数据丢失？[ ]　启动>3s 无响应？[ ]　交互失效？[ ]
## 修复清单（若 NEEDS WORK）
| # | 问题 | 严重度 | 建议 |
```

## T6. 交接包模板（阶段之间传递，原样粘贴不摘要）

```markdown
## Phase X → Phase Y Handoff
### 携带文档：[上阶段全部产出列表]
### 关键约束：[合规 / 性能 / 平台约束]
### 待办优先级：[1, 2, 3]
### 环境与入口：[仓库 / CI / 产物位置]
```

## T7. 发布检查表（阶段 7 速查）

```
[ ] 版本号 / CHANGELOG / tag 一致
[ ] 安装包 + 主程序 + 更新清单全部签名并验证
[ ] 干净机器三走查（新装/升级/卸载）截图归档
[ ] 更新通道：灰度 1% 配置 + 回滚操作卡
[ ] 下载页：SHA-256、隐私政策、常见问题
[ ] 崩溃上报看板在线
[ ] 发布说明（用户语言）已写
```

## T8. 经验记录模板（阶段 8，每次发布后回填）

```markdown
# 发布复盘 vX.Y.Z
- 指标对 North Star：[达标/未达 + 数字]
- 本期踩坑：[平台雷区 / 签名 / 更新 / 性能]
- 测试为什么没抓到：[补测试 / 补检查项]
- 写回 skill 包的改动：[改哪个文件哪一节]
```
